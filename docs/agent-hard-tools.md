# 设计提案：不把 Agent 接到扫描器后面，而是给 Agent 一组硬工具

> 状态：提案，尚未接入当前主扫描链路。当前版本已移除扫描 Worker 内部的旧 LLM 后处理路径。

> 讨论起点：我们有一个比较完备且高度解耦、流程化的静态扫描器。把其中的一个个功能拆成对应的小工具，LLM 提供语义理解能力，拆出来的功能完备的构件提供可调用、可核验的静态分析能力。由此形成一个体系：agent 可以提出假设、改变调查方向、追查陌生机制；工具负责提供当前字节码中的事实，以及这些事实能够支持的结论。这样也就实现了"假设不成立时的回调"，以及多方向的探索。

这个理解方向是对的，而且恰好是这个仓库当前形态的自然下一步。下面把它展开成一个可以指导落地的框架，并补上几个原表述里没有覆盖、但决定成败的细节。

## 一、两种形态的本质区别

**形态 A：Agent 接在扫描器后面（后处理器形态）**

```
[固定流水线] → [固定产物] → [LLM 总结/研判]
```

这是本仓库现在的样子：CodeQL 跑完固定规则 → SARIF 入库 → `AppSecAuditor.AnalyzeVulnerabilityWithLogger` 对每条 finding 做语义研判。它的天花板很低：

- LLM 只能在**既定产物**上做二次解读，扫描器没覆盖的路，LLM 再聪明也看不见；
- 整条 pipeline 对 LLM 是黑盒，LLM 无法在"这一步的结果显示方向错了"时回头；
- 语义能力的价格被浪费在"给固定结论润色"上。

**形态 B：Agent 拿着一组硬工具（编排者形态）**

```
[LLM 假设/规划] ⇄ [工具调用] → [可核验的事实] → [证实 / 证伪 / 转向]
```

这是目标形态。关键变化不是"多了个 LLM"，而是**控制流的所有权转移了**：下一步做什么，从流水线的 `for` 循环手里，交给了能被事实说服、也能被事实驳倒的 agent。

## 二、这个体系的正确切法：三层分离

把"扫描"这个混沌的概念拆成三层，每层的责任、实现者和性质都不同：

| 层 | 职责 | 实现者 | 性质 |
|---|---|---|---|
| **事实层** | 生产可核验的事实：谁调用谁、数据流到哪、端口开没开、指纹是什么 | 硬工具（从扫描器拆出的构件） | 确定性、可复现、自带证据 |
| **结论层** | 判断事实支持什么结论：这是漏洞吗？是误报吗？危害多大？ | LLM | 语义理解，必须引用证据 |
| **决策层** | 决定下一步：证实、证伪、转向、深挖、停止 | Agent loop | 假设驱动的探索 |

原表述里"工具负责提供事实，以及这些事实能够支持的结论"这句要小心：**事实是工具的，结论是 LLM 的**。工具最多提供"事实的既定解读"（比如某条指纹规则的语义标签），而"这些事实加起来意味着什么"永远应该留给 LLM——一旦让工具直接输出结论，就等于把 LLM 的语义判断降级成了规则匹配，回到形态 A。

这个分离还有一个副产品：**可审计性**。安全产品的每一条最终结论都能回溯成一条证据链（工具调用序列 + 每步的事实输出），误报可以归因——是事实层错了（工具 bug），还是结论层错了（LLM 幻觉），还是决策层错了（调查方向）。这是"扫描器 + LLM 总结"永远给不了的。

## 三、硬工具的设计原则（决定成败的部分）

拆工具不是拆得越细越好。以下原则按重要性排序：

### 1. 粒度 = 一个可证实/可证伪的问答单位

- 太细（`read_byte(offset)`）：agent 淹死在成千上万次调用里，语义预算花在搬运上；
- 太粗（`full_scan(target)`）：退化为形态 A，只是换了个皮肤；
- **正确粒度**：一次调用恰好回答一个 agent 真的会问的问题。"这个函数的调用者有哪些？""这条 source 到 sink 的路径经过哪些净化函数？""这个端口的 TLS 证书是谁签的？"

本仓库的 DAST 引擎其实已经是这个粒度的雏形：`portscan.NativeGoScan`、`TLSAnalyzer.AnalyzeTLS`、`FingerprintEngine.DetectWebTechnologies`、`ExtractEndpointsFromHTML` 都是单一职责的纯问答函数。`Runner.Run` 的五阶段只是对它们的一种**固定编排**。

### 2. 否定语义必须三分，否则"假设不成立的回调"是假的

这是原表述里没有、但对"回调"最致命的一点。工具返回"没有"时，必须区分：

| 语义 | 含义 | 对 agent 的作用 |
|---|---|---|
| `NOT_FOUND` | 查了，确实没有 | **构成证据**，支持"假设不成立"，可以回溯 |
| `UNSUPPORTED` | 这类查询我的分析模型覆盖不了（如反射调用、动态加载） | **不构成证据**，不能用来证伪 |
| `ERROR` | 我坏了（超时、解析失败） | 不构成任何证据，可重试 |

如果工具把三者混成一个空结果，agent 的回溯逻辑就被系统性污染：它会把"工具看不见"当成"事实不存在"，在错误的负结果上放弃正确假设，或者在正确的负结果上无休止地换工具重查。CodeQL 这类静态引擎的 soundness 边界（哪些调用图边它不建）必须在工具契约里显式声明给 LLM。

### 3. 输出必须自带证据，禁止裸结论

工具的返回值应该是 `{事实, 证据(位置/路径/原始字节), 置信度, 工具自身的可靠性边界}`，而不是一个布尔或一句话。原因有二：

- LLM 的结论必须可回溯。没有证据引用的 LLM 判断，和幻觉无法区分；
- DAST 场景下，工具的输入（HTTP 响应体、页面内容）是**不可信输入**。证据字段让安全团队能检查"这个事实是真实目标返回的，还是注入进来的"。工具产物流经 LLM 时，一律按 untrusted data 处理——否则就是给目标一个往 agent 大脑里写 prompt 的通道。

### 4. 确定性 + 可缓存 + 成本不对称

同一输入必须同一输出：温度为零的世界全部交给工具，语义模糊全部交给 LLM。工具调用应当便宜、可缓存、可并行（对同一个目标的重复问答直接命中缓存）；LLM 推理昂贵。架构上要鼓励"先用工具暴力收窄假设空间，再用 LLM 做最后一步语义判断"，而不是让 LLM 靠读原始字节码自己当扫描器。

### 5. 声明式能力发现

每个工具用 schema 描述自己"能回答什么问题、需要什么输入、结果可靠到什么程度"。agent 遇到陌生机制时（一个没见过的框架、一个奇怪的协议），靠读工具清单就能组合出调查路径（查 import → 查调用链 → 查配置解析点），而不需要人预先写好流程。这正是"追查陌生机制"能力的来源：**组合的多样性不需要预先编排**。

## 四、落到本仓库

现有资产和目标形态的距离比想象中近：

1. **DAST 侧**：`Runner.Run`（pipeline.go）的五阶段——目标解析、端口探活、服务识别、POC 验证、去重报告——本来就是把独立函数串起来的编排层。把编排层从 `for` 循环改写成 agent 的 tool-call schema，五个阶段就是五个现成的硬工具；`RateLimiter` / `BudgetTracker`（dedup.go）直接复用为 agent loop 的资源治理。
2. **SAST 侧**：`codeql.go` 本来就是 CodeQL CLI 的封装，天然可拆成三个工具：`创建数据库`、`执行单条 .ql 查询`、`解析 SARIF 为结构化事实`。现在的 `ScanWorker` 是对它们的固定编排，同样保留为"自动模式"。
3. **双模式共存**：pipeline 不废弃。它是**预算受限时的自动驾驶**（批量扫描 CI 任务），agent 是**专家调查模式**（0-day 挖掘、单目标深查）。两者共享同一套工具实现，这正是"高度解耦、流程化"前期投入的红利——pipeline 本身就是对工具的一种合法编排，只是固定而已。判定一个功能该不该拆成工具的试金石：**agent 会不会用它来证实/证伪某个假设**。会，拆；不会（比如批量端口扫描的并发调优细节），留在 pipeline 内部。
4. **Agent loop 的骨架**：`假设 → 工具调用 → 证据 → 证实 / 证伪 / 分支 / 放弃`，配上 `BudgetPolicy` 式的步数/调用数/每假设预算上限，和一条"证据链日志"（每次工具调用的输入输出全量落盘，事后可回放审计）。

## 五、诚实的边界

- **幻觉不会被消灭，只会被关进笼子。** 三层分离保证幻觉只发生在结论层，且必须引用证据；但 LLM 仍可能对证据过度解读。结论层需要独立复核（可以让另一个模型实例只看证据链做 adversarial review）。
- **探索爆炸是常态。** "多方向探索"的另一面是无边的分支。没有预算治理的 agent 会把 token 烧在无穷的次要假设上。停止条件需要一个显式判据（证据收敛 / 预算耗尽 / 假设空间穷尽），不能靠模型自觉。
- **工具质量成为新的瓶颈。** 形态 A 里扫描器的漏报藏在流水线后面没人知道；形态 B 里工具的 `UNSUPPORTED` 边界直接暴露给 agent，也直接决定它的推理上限。工具的覆盖面声明本身就是资产，要像维护规则库一样维护它。

## 结语

一句话版本：**扫描器是生产事实的工厂，agent 是消费事实的侦探；侦探不能伪造证据，工厂不该越权推理。** 把静态分析从"产品"降维成"原语"，把 LLM 从"后处理器"升维成"编排者"——原表述里"可调用、可核验"四个字，就是这个架构的全部要点：可调用让 agent 有手，可核验让 agent 有腿（能被驳倒、能回头）。
